# Запуск на Android и iPhone

PocketFleet — учебное приложение на React Native, а не настоящий MDM-агент. Здесь есть реальная клиент-серверная регистрация, нативное чтение модели/версии ОС и защищённое хранение токена. Блокировка ОС, удалённое управление экраном и применение системных ограничений не реализованы.

## 1. Демо без регистрации

Установи Node.js 22.19 или новее. Из каталога проекта:

```powershell
npm ci
npm run check
npm start
```

Установи совместимый с Expo SDK 57 Expo Go. На Android отсканируй QR-код в Expo Go, на iPhone — через камеру. Компьютер и телефон должны находиться в одной сети. В демо используются явно помеченные вымышленные данные.

Если установленный Expo Go требует другой SDK, это несовпадение версий, а не повод произвольно обновлять отдельные пакеты. Используй совместимый Expo Go или development build. Для iOS доступность установки старых Expo Go ограничена; при необходимости нужна облачная development-сборка с корректной подписью. Не обещай готовый IPA/APK, пока сборка действительно не получена.

## 2. Реальное подключение своего телефона

В отдельном терминале из каталога проекта:

```powershell
$env:POCKETFLEET_HOST="0.0.0.0"
npm run server
```

Сервер напечатает локальные адреса. Не используй на физическом телефоне `127.0.0.1`: это адрес самого телефона. Возьми LAN-адрес компьютера, например `http://192.168.1.10:4347`. Только доверенная домашняя Wi-Fi-сеть; не открывай порт наружу. Если подключение блокирует брандмауэр, проверь разрешение для конкретного приложения в частной сети, не отключай брандмауэр целиком.

Пример с локальным HTTP предназначен для разработки через Expo Go. Самостоятельные native-сборки сохраняют ограничения транспорта Android/iOS: для них настрой HTTPS на своём сервере. Глобальные исключения ATS/cleartext в проект намеренно не добавлены.

В третьем терминале:

```powershell
npm run admin -- code
```

В приложении открой Connection, введи URL, имя телефона и код, подтверди согласие. Код действует 10 минут и только один раз. Для второго телефона выпусти новый код.

В инвентаризации должны появиться **реальные** модель и версия ОС. Веб-версия честно сообщает `Browser preview`, не выдавая браузер за Android или iPhone.

## 3. Сценарий демонстрации на 3–5 минут

1. Открой Device и покажи реальный телефон в инвентаризации.
2. Выполни `npm run admin -- devices`, скопируй ID своего устройства.
3. Выполни `npm run admin -- message ID "Hello from my lab"`.
4. До синхронизации команда имеет статус `queued`. Нажми Sync; приложение получает её и отправляет подтверждение. В журнале появляется `acknowledged`, а напоминание видно на Device.
5. Выполни `npm run admin -- inventory ID`: приложение заново собирает минимальную инвентаризацию.
6. Измени baseline: `npm run admin -- policy android 30`. После синхронизации правило станет `Review`. Это **оценка**, а не блокировка ОС. Верни разумное значение.
7. Отключи сеть телефона, нажми Sync и покажи, что предыдущие данные остаются доступными. Верни сеть и повтори синхронизацию.
8. Сверни приложение: в фоне опрос не работает. После возвращения приложение возобновляет синхронизацию.
9. Отзови токен через `npm run admin -- revoke ID`; очередной запрос больше не авторизуется. Отключи сессию в приложении.

При первом запуске кэш/токен могут отсутствовать — это нормальный сценарий, не ошибка. Токен и одноразовый код нельзя помещать в скриншоты, Git или резюме.

## 4. Что изучить перед добавлением в резюме

- `shared/contracts.ts`: валидация, различие платформ, состояние `unknown`, ограничение HTTP локальной сетью.
- `server/store.ts`: одноразовый код, хеширование токена, транзакции, состояния команд.
- `src/core/sync.ts`: зачем outbox сохраняется до отправки результата и почему доставка не равна выполнению.
- `src/mobile/storage.ts`: Keychain/Keystore, отличие секретов от кэша, почему браузерный fallback только в памяти.
- `src/mobile/FleetProvider.tsx`: жизненный цикл, отмена запросов и защита от устаревшей сессии.
- `tests/`: прогони тесты и измени хотя бы одну проверку или правило самостоятельно.

Вопросы для самопроверки: что будет, если сервер принял результат, но ответ потерялся? Где проверяются права? Можно ли доверять версии ОС, присланной клиентом? Почему приложение не может просто запретить камеру на чужом телефоне?

## 5. Честная формулировка для резюме

После собственного запуска и разбора:

> **PocketFleet, учебный проект.** Кроссплатформенное приложение для Android/iOS на React Native, Expo и TypeScript с локальным API на Node.js/Fastify и SQLite. Регистрация по одноразовому коду, защищённое хранение токена, инвентаризация устройства, оценка политик, журнал команд и повтор отправки результатов при сетевых сбоях. Автоматизированные проверки контрактов, API и синхронизации.

Добавляй «проверено на Android и iPhone» **только после реальной проверки на обоих устройствах**. Не называй проект полноценной MDM-системой, коммерческой разработкой или опытом Swift/Kotlin. Не гарантируется, что наличие проекта само по себе изменит решение работодателя.
